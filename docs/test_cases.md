# Test Cases

**Test run:** 2026-11-07, Windows 11, Python 3.11.9 (project `.venv`), PySpark 3.5.1, PostgreSQL 16, Spark started with default settings (5 s trigger, max 10 files per trigger).

**Setup:** The file-clearing steps of `scripts/reset_pipeline.ps1` were run (input CSVs, checkpoints, `data/rejected`, `logs/batch_metrics.csv`). Its database step (`psql -U postgres -f postgres_setup.sql`) needs the postgres superuser password interactively, which wasn't available. Instead, `TRUNCATE events, events_staging;` was run as `ecommerce_user`, after checking that the live schema matched `postgres_setup.sql`. Then `SELECT COUNT(*) FROM events;` returned **0**. TC-01–TC-05 files were moved out of `data/input/` before Spark started, so Spark only saw the TC-06+ runs.
